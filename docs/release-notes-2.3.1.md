# SIR 2.3.1 — Failure-mode hardening

SIR 2.3.1 changes only failure paths that previously crashed or silently fell
back to built-in domain-pack defaults. Valid inputs retain their existing gate
decisions, and existing signed certificates remain unchanged and verifiable.

## Domain-pack schema enforcement

- Domain ISC packs now require a matching non-empty `pack_id`, configurations
  for every identifier derived from the built-in allowed-template set, a
  positive native JSON integer `max_tokens` for each template, and native JSON
  booleans for all three enforcement flags.
- `STRICT_ISC_ENFORCEMENT` remains required for schema compatibility but is not
  currently consulted. ISC structural rejection is unconditional.
- Malformed pack JSON or a parsed pack that fails validation returns
  `systemic_reset_domain_pack_invalid`, distinct from the existing
  `systemic_reset_domain_pack_load_failed` result used when a pack cannot be
  found or read.
- All six existing packs already used native JSON integers and booleans.
  Removing `int(...)` and `bool(...)` coercion from domain-pack application
  therefore changes no valid current pack behavior.

## Internal failure boundary

- Exceptions not handled by an existing targeted validation path now return a
  `systemic_reset_internal_error` block rather than escaping to the caller.
- The internal-error ITGL entry records the exception type and message for
  diagnosis. Existing policy-load and domain-pack handlers remain the primary
  targeted paths.
- Structured JSON parsing now treats `MemoryError` like `RecursionError` and
  returns `structured_invalid_json`. A process-level out-of-memory kill cannot
  be caught in-process and is outside this guarantee.

## Compatibility and evidence

- Gate-outcome invariance properties remain green.
- Published deterministic and full-gate coverage figures are unchanged and
  continue to match the coverage generator.
- `proofs/latest-audit.json` and `proofs/latest-live-audit.json` remain valid
  historical SIR 2.3.0 certificates and continue to verify without changes.
- No policy file, domain pack, benchmark suite, published certificate, or
  archived evidence artefact is regenerated by this release.
