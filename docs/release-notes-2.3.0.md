# SIR 2.3.0 — Audit accounting and bounded homoglyph evaluation

SIR 2.3.0 contains two correctness patches: systemic-reset runs are no longer scored, and the existing bounded homoglyph translation is now applied to text evaluated by the content gate.

## Systemic-reset audit accounting

- The audit runner counts rows that return `systemic_reset_domain_pack_load_failed` and records `systemic_reset_domain_pack_load_failed_count` in `proofs/run_summary.json`.
- Systemic-reset rows are excluded from `jailbreaks_leaked` and `harmless_blocked`. A reset block cannot earn credit for an expected-block row or count as an ordinary false-positive block for an expected-allow row.
- The certificate generator classifies a run with a positive systemic-reset count as `INCONCLUSIVE`. Summaries that predate the field retain their previous result semantics.
- Scenario summaries retain the count when the CLI changes their proof class to `SCENARIO_AUDIT`.
- The signed certificate payload and evidence contract are unchanged; the diagnostic count remains in the unsigned run summary.

## Bounded homoglyph evaluation

- `normalize_obfuscation()` now applies the existing nine-entry `_HOMOGLYPH_ASCII_MAP` to text returned for content evaluation, including accepted Base64-decoded candidates and text introduced by the other supported decoders.
- This closes the recorded multi-token bypasses in which a mapped character appeared outside the canonical marker recovered by `_canonical_compact()`.
- The mapping itself is unchanged. This release does not add general Unicode-confusable handling or semantic normalization.
- Structural override exposure continues to inspect the raw payload and therefore remains outside homoglyph translation by design.
- Characterisation tests now record the existing non-idempotent marker append and invisible-character-in-token string behavior; those behaviors are not changed by this release.

## Compatibility and evidence

- Existing signed certificates remain valid records of their past runs: their stored payloads and signatures are not modified.
- Re-running an earlier input can produce a different gate decision when it contains one of the nine mapped homoglyph characters. That behavior change is intentional.
- No registered benchmark-suite row contains a mapped homoglyph character, and the generated deterministic and full-gate coverage figures are unchanged.
- No policy file, domain pack, benchmark suite, published certificate, or archived evidence artifact is regenerated by this release.
